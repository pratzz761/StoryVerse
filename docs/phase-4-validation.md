## Security checks and practical limits

- Production refuses the shared demo identity/local filesystem persistence, HTTP/localhost cloud configuration, arbitrary CORS origins, direct cloud-to-local image mode and unacknowledged moderation.
- Readiness verifies the private bucket and an assigned moderator before public writes are considered ready. Empty/missing hosted migrations produce 503. Health/configuration alone is not provider verification.
- Supabase Auth verifies bearer sessions server-side; production requires confirmed email. Caller JWTs retain RLS on ordinary operations. Service keys remain server-only and are used for protected queue/generation RPCs and owner-private remote uploads. Key-format header behavior is covered by mocks, not hosted Gateway tests.
- Another user cannot read a queued job through the owner API; browser roles cannot read/claim/finish worker queue rows. Wrong leases/expired results fail; a second worker receives no job while one lease is active. Successful finish/replay uses the same saved version through existing atomic publication logic.
- Worker callback retries use the saved PNG and same upload/job UUID, not another GPU render. Metadata checks include checkpoint, dimensions, settings, seed, prompt hash, image hash and actual ComfyUI execution ID. No untrusted returned URL is fetched. Both HTTPS certificate verification and redirect refusal remain enabled.
- PNGs use the existing validation and Supabase Storage flow; only referenced approved images become public. Stale results may leave a private orphan, which requires operator cleanup. The 30-object Storage capacity guard also covers privileged uploads.
- Private reports, immutable moderator role assignments and audited hide/restore were tested in SQL. Hidden stories disappear from discovery, chapter/canon queries, upload metadata and Storage object reads. No automatic semantic/image moderation or CAPTCHA widget is claimed.
- Durable daily/rate/concurrency limits for Gemini/image jobs remain. Additional database triggers limit manual content and upload metadata; raw Storage object capacity is bounded too. These protect normal/direct-API user writes, not unlimited DDoS or account farming. The global in-memory request circuit breaker is explicitly single-process, not a distributed or IP-proof limiter.
- Oversized bodies are rejected; responses are non-cacheable with MIME sniffing disabled. Startup validation and API error handling redact input/SDK chains. A synthetic exception regression verifies that private exception text reaches neither response nor captured server log.
- Browser prose/report fields render as text. Media types/signatures, AI schemas, canon, draft versions and explicit publication consent remain enforced. Human review is still required for unsafe material, factual/visual errors and abuse.
